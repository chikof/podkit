Thought for 4.1 s

The user wants a Containerfile for a Rust axum service with a small runtime image. Build in a rust:1.88 stage and use cargo-chef so dependency layers cache. A distroless cc image is enough because axum links glibc dynamically. Run as nonroot, expose 8080, and copy only the release binary. A .dockerignore for target/ is worth mentioning.

Here is a two-stage Containerfile. Dependencies are cached in their own layer with cargo-chef, and the final image is distroless, so there is no shell and no package manager to patch.

FROM docker.io/library/rust:1.88 AS chef
RUN cargo install cargo-chef --locked
WORKDIR /src

FROM chef AS plan
COPY . .
RUN cargo chef prepare --recipe-path recipe.json

FROM chef AS build
COPY --from=plan /src/recipe.json .
RUN cargo chef cook --release --recipe-path recipe.json
COPY . .
RUN cargo build --release --bin api

FROM gcr.io/distroless/cc-debian12:nonroot
COPY --from=build /src/target/release/api /api
EXPOSE 8080
ENTRYPOINT ["/api"]

Add target/ and .git to .dockerignore so the build context stays small. With Podman, podman build -t api . works unchanged.
